# Terraform (AWS deployment)

Provisions HeadStart on AWS ECS Fargate.

- **First-time deploy walkthrough:** [../../docs/deploying-to-aws.md](../../docs/deploying-to-aws.md)
- **Architecture / module layout:** [../../docs/modules/deployment.md](../../docs/modules/deployment.md)

## Layout

```
modules/
  network/   security/   ecr/   secrets/   iam/   alb/   rds/   redis/   ecs/
  stack/     # composes all of the above into one environment
environments/
  beta/   prod/   # thin wrappers: provider + remote state + module "stack"
                  # distinct VPC CIDRs (beta 10.20/16, prod 10.30/16)
```

## One-time bootstrap (remote state)

State lives in S3 with a DynamoDB lock table. Create them once from the repo root:

```bash
just terraform-bootstrap PREFIX=YOURNAME AWS_REGION=us-east-2
```

Committed `backend.tf` files are a **partial** S3 config: they set the state
`key`, default `region`, lock table, and encryption, but **omit the bucket**
so a real bucket name is never committed. Pass the bucket at init:

```bash
cd environments/beta
cp backend.hcl.example backend.hcl   # gitignored; edit YOURNAME-headstart-tfstate
terraform init -backend-config=backend.hcl
```

Or use `just aws-first-deploy`, which passes `-backend-config=bucket=…` for you.

## First-time deploy (one command)

From the repo root (AWS creds + Terraform + Docker required):

```bash
just aws-first-deploy PREFIX=YOURNAME AWS_REGION=us-east-2
```

See [../../docs/deploying-to-aws.md](../../docs/deploying-to-aws.md#quick-start-one-command).

## Deploy an environment

```bash
cd environments/beta
export TF_VAR_db_password="$(openssl rand -base64 24)"
export TF_VAR_jwt_secret="$(openssl rand -hex 32)"
export TF_VAR_credentials_secret_key="$(openssl rand -hex 32)"
cp backend.hcl.example backend.hcl   # set bucket = "YOURNAME-headstart-tfstate"
terraform init -backend-config=backend.hcl
terraform plan
terraform apply
```

Outputs include `app_url`, `alb_dns_name`, and `ecr_repository_urls`.

## First image push + migrations

The ECS services need images in ECR before they can run. From the repo root:

```bash
eval "$(just aws-deploy-env)"
just deploy
```

## Conventions

- Secrets are never committed. Provide `db_password` / `jwt_secret` /
  `credentials_secret_key` (and `smtp_password`) via `TF_VAR_*` env vars.
  `terraform.tfvars.example` documents those as shell exports only.
  Non-secret knobs may use a local `terraform.tfvars` (gitignored). Values are
  stored in AWS Secrets Manager and injected into ECS tasks at runtime.
  `REDIS_PASSWORD` and `METRICS_TOKEN` are generated by Terraform
  (`random_password`) and always injected. Retrieve `METRICS_TOKEN` from
  Secrets Manager when configuring Prometheus scrapes.
- `prod` enables Multi-AZ RDS, 30-day DB backups, 90-day ECS log retention,
  RDS + ALB deletion protection, and Multi-AZ Redis with automatic failover;
  `beta` stays minimal/cheap (7-day backups, 30-day logs, single-primary Redis
  with encryption/AUTH, no Multi-AZ failover). See
  [docs/modules/deployment.md](../../docs/modules/deployment.md#prod-resilience-knobs).
- Environments pin distinct VPC CIDRs (`beta` `10.20.0.0/16`, `prod`
  `10.30.0.0/16`) so peering / shared routing cannot collide. See
  [deployment.md](../../docs/modules/deployment.md#distinct-vpc-cidrs).
- Every environment's ALB drops invalid headers, ships access logs to a private
  S3 bucket, and attaches a regional WAFv2 ACL (AWS Managed Common + Known Bad
  Inputs). See [deployment.md](../../docs/modules/deployment.md#alb-hardening).
- Prod `image_tag` is required and must not be `latest` (immutable git SHA
  pin). Beta may still default to `latest` for throwaway stacks; `deploy.sh`
  retargets task defs to `IMAGE_TAG` on every roll either way.
- Prod requires HTTPS (`domain_name` + `route53_zone_id`, or
  `acm_certificate_arn`); the stack check `prod_requires_https` fails
  plan/apply if the ALB would forward auth traffic over plaintext HTTP.
  Beta may still use the HTTP ALB DNS name.
- ECS service + task family names are stable (`headstart-api`, etc.) so the
  same `deploy.sh` works against any environment's cluster. `deploy.sh`
  registers a new task-definition revision per family pinned to the just-pushed
  `IMAGE_TAG` before rolling services (Terraform's `image_tag` is only the
  initial pin; ECS `ignore_changes` on `task_definition` leaves rolls to deploy).
